How it works

Five sports, one server. The market price leads, the model sits beside it, and every pick stays on the record.

From raw data to a pick

    One server runs everything

    1. Push to mainany site's code
    2. GitHub Actionsbuilds the image
    3. Registryghcr.io, tagged by commit
    4. Deploypull, restart, health check
    5. Unhealthy?rolls back to the last tag
    OVH VPSUbuntu · Docker Compose · 4 GB
    Caddythe only open door: HTTPS for every *.40-160-91-131.sslip.io name, routes each to its container
    New data never needs a redeploy
    • PL, F1, NFL, CFB: a scheduled GitHub Action rebuilds public_snapshot.json and commits it; the running app re-reads it from GitHub every 5 minutes.
    • NBA is the exception: two timers on the server run its pipeline inside the container (scores every 10 minutes; refresh, retrain and re-score daily at 13:40 UTC), and its pick record lives on a disk volume that survives redeploys.
    • Deploys are automatic for all seven repos. A push to main on PL, F1, NBA, NFL, CFB, the sports frontend or this hub runs that repo's deploy workflow, which runs deploy <site> <commit> over SSH. That command is the only thing the CI key may run on the server.
    • The hub deploys by checking out the commit into a fresh folder and swapping a link, so a half-copied page is never served.

      Every pick counts, once

      One counted pick per game × player × stat = the earliest recorded
      First recordcounted, never overwritten
      Model rerunkept on file, not counted again
      Kickoff
      After kickoffif it's the first record, it counts, labelled
      A rerun can't improve the record
      • The models are rerun often. The earliest recorded pick for a game, market and player is the one scored, so a later, better-informed rerun never replaces it or counts twice.
      • The headline is every counted pick; the figure beside it is the subset made before kickoff. A pick made after kickoff is labelled, never hidden.
      • The same rule grades player props: the earliest projection per game, player and stat.

      Paper bets, settled for real

      1. Log15:45 · 23:35 UTCeach Kalshi rung the model would buy, at the ask, after the price collectors run
      2. Closeevery 15 mincaptures the closing price for bets starting within 45 minutes
      3. Settle04:20 · 12:20 · 20:20 UTCfrom Kalshi's own result, fees included
      4. Verdictper sportproven, leaning, against, or not yet

      Loading the ledger…

      Proven
      P&L interval above zero and the model beats the price on log-loss
      Leaning
      enough bets, average P&L positive, not proven yet
      Against
      P&L interval below zero, or the market is clearly better
      Not yet
      under 100 settled bets or 50 games (F1 20, PL 60)
      The ledger can't be edited after the fact
      • Append-only: a bet is written once, at the first price that qualifies. Settlement and price updates are new lines, never rewrites.
      • The price must come from before the start, and the model's number must be published before that price, or the row is a shadow: logged, never staked.
      • Only buyable prices: YES at the ask, NO at the ask. A dead or crossed quote is not logged. No real money, no account, no order code.
      • Full tables: Paper Trading.

      A model change ships only on evidence

      1. Walk-forwardtrain on the past, test on the next season, never tune on the test
      2. Clear of zeropaired bootstrap 95% interval on the main metric, entirely on the better side
      3. Nothing worseno other reported metric gets worse; a fail ships a write-up, not code
